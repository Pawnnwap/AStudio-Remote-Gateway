# AStudio-Remote-Gateway（非官方）

> **⚠️ 非官方声明与免责声明见文末「免责声明」章节。本项目与 iFlytek（讯飞）/ AStudio 无任何关联，仅通过本地进程间机制实现个人自动化。**

通过 IM（**飞书试点**，钉钉/QQ 可按同一契约扩展）远程指挥本机 AStudio 的对话：
列出已有会话、进入对话、直接发文字指挥、执行中插话/停止、切换模型、调度全新任务。
全程复用 AStudio 登录态，**不配置任何 API key**。

```
飞书（试点）/ 钉钉 / QQ …        ← 渠道适配层，一个渠道一个 adapter
      ↓ 统一网关契约：handle_message(open_id, text) -> reply（异步，见「接入新渠道」）
网关核心（渠道无关：命令解析 + 任务注册表 + 上下文持久化 registry.json）
      ↓ AStudio 两条通道（零 API key，全部复用登录态）
  ① App 控制面 MCP     ：读线程/发消息/列模型/打断（会话执行中即时插话）
  ② 自动化调度器       ：直写一次性自动化定义（空闲会话 ≤1 分钟自主投递/新建任务）
```

## 核心能力（均端到端实测）

| 能力 | 实现 |
|---|---|
| 会话发现 | `/sessions` 只读枚举 AStudio 已有对话；按最近活跃排序，`●执行中` 标记，序号按创建固定 |
| 进入对话 | `/task <序号>`：接管该对话（幂等，重复执行即切回） |
| 远程指挥 | 直接发文字投递到当前对话，界面实时可见。会话空闲时经 App 自动化调度器投递（官方 tick ≤1 分钟）；执行中即时 |
| 忙碌闸门 | 任务执行中拒收新指令并提示；`/steer <插话>` 引导当前回合；`/stop` 真实打断 |
| 切换模型 | `/model <slug>`：经自动化改绑线程模型，持久生效（内置模型直接切；custom 绑定自动补全 customModel） |
| 切换即投递 | `/model <slug> <消息>`：一步换模型并发消息（无单独切换回合；连续空白自动压缩；失败自动回滚模型） |
| 调度新任务 | 没有任务时直接发文字：App 新建对话执行你的指令并自动绑定为当前任务 |
| 上下文读取 | `/history [条数]`：实时读当前对话内容 |
| 渲染与交互 | 回复以 markdown 卡片发送（失败自动降级纯文本）；支持机器人底部菜单 |

## 环境要求

- Windows + AStudio 桌面版（已登录），使用期间保持运行
- Python 3.10+；飞书 SDK 二选一（见下「依赖」）
- 一个飞书自建应用（个人可免费创建企业后自建自审，见下）

## AStudio 端配置（一次性）

1. **安装 AStudio 桌面版并登录**——登录态是全部模型通道的凭证来源，本项目不配置任何 API key。
2. **使用网关期间保持 AStudio 运行**。三个依赖都活在 App 进程里：内置 MCP 服务（动态端口，网关自动发现）、本地模型网关、自动化调度器。
3. 在界面里**正常创建对话并至少成功跑过一个回合**。`/sessions` 发现只要求有消息；进入（takeover）要求存在内核会话绑定，跑过回合即有。
4. 路径全部自动探测；非默认安装位置才需要环境变量覆盖（见下「配置项」）。
5. **验证**：`python main.py --mock` 后输入 `/sessions`，能列出对话即配置完成。

说明：
- 本项目对 AStudio 数据**只读**（发现/进入绑定）；唯一的写入是自动化定义表（官方投递机制）与 App MCP 工具调用。
- AStudio 大版本升级若改动内部端口/表结构，网关按动态发现实现通常无需改动；异常时重启 AStudio 即可恢复凭证新鲜度。

1. 登录[飞书开放平台](https://open.feishu.cn/app)。**需要企业身份**：个人可免费「创建企业」（团队版），自己即管理员，后续审批全部秒过。
2. 开发者后台 → **创建企业自建应用**，随意命名（如 `AStudio Gateway`）。
3. 「凭证与基础信息」页：复制 **App ID**（`cli_` 开头）与 **App Secret**。

### 2. 添加机器人能力

应用能力 → **添加应用能力** → **机器人**。

### 3. 事件订阅（长连接，无需公网 IP）

事件与回调 → 订阅方式选 **「使用长连接接收事件」** → 添加事件 **「接收消息 im.message.receive_v1」**。
（如需菜单点击为事件形态，可另订阅 `application.bot.menu_v6`；用「发送文字消息」型菜单则不需要。）

### 4. 开通权限（权限管理页）

| 权限 | 用途 |
|---|---|
| `im:message` | 获取与发送单聊、群组消息 |
| `im:message.p2p_msg:readonly` | 读取用户发给机器人的单聊消息 |
| `im:message.group_at_msg:readonly` | 接收群聊中 @机器人消息（群聊场景需要） |
| `im:message:send_as_bot` | 以应用身份发消息（回复） |

### 5. 发布

版本管理与发布 → 创建版本 → 发布（自建企业管理员即自己，秒批）→ 确认**可用范围**包含自己。

### 6. 机器人菜单（可选但推荐，精简 3 项）

应用能力 → 机器人 → 机器人自定义菜单 → 添加菜单项，响应动作选 **「发送文字消息」**：

| 菜单名 | 发送内容 |
|---|---|
| 会话列表 | `/sessions` |
| 当前任务 | `/task` |
| 帮助 | `/help` |

→ 再次**发布版本** → 等 5 分钟生效。点击菜单即发送对应命令；网关对菜单名文本与命令文本都能识别（也可用「推送事件」型菜单项，事件键填命令即可）。

### 7. 验证

在飞书里搜索应用名，**私聊机器人**发送 `/sessions` —— 应回 AStudio 会话列表。

## 网关端配置与启动

1. 克隆本仓库，安装依赖（见下「依赖」）。
2. 复制 `start_feishu.ps1.example` 为 `start_feishu.ps1`，填入 App ID / App Secret。
3. 启动：

```powershell
powershell -ExecutionPolicy Bypass -File start_feishu.ps1
# 等价于：
#   $env:FEISHU_APP_ID = "cli_xxxx"; $env:FEISHU_APP_SECRET = "xxxx"
#   python main.py
```

看到 `飞书长连接启动中（app_id=cli_…）` 即连上。之后给机器人发 `/sessions` 开始使用。

### 依赖

```
pip install -r requirements.txt
```

- **psutil**（必需）：进程发现、环境变量读取、内存扫描
- **飞书 SDK**（二选一，网关自动适配，优先本地 vendor）：
  - 方式 A（推荐，离线可用）：`pip install lark-oapi` 后把 site-packages 里的 `lark_oapi` 目录复制为仓库下 `vendor/flark/`
  - 方式 B：直接 `pip install lark-oapi`，网关检测到无 vendor 时自动改用官方包
- 其余全部为 Python 标准库（无数据库、无运行时服务、无 API key）

### 用户命令

```
/task                      当前任务详情（含执行状态）
/task <序号>               进入对话（序号同 /sessions；重复执行即切回）
/task del <序号|名>        删除任务
/sessions                  列出 AStudio 已有 对话
/model [模型] [消息]       查看/切换模型并直接投递（一步完成，如 /model xopglm52 做个登录页）
/history [条数]            读取当前对话内容
/status                    当前状态总览
/stop                      停止当前正在执行的回合
/steer <插话>              执行中插话引导方向
/help                      帮助
直接发文字 = 指挥当前任务；没有任务时 = 调度一个全新 任务。
```

## 接入新渠道（钉钉 / QQ）

> 渠道优先级（已调研官方政策）：**钉钉 Stream 模式**（免费建组织 + 官方 WebSocket 长连接）>
> QQ 官方平台（个人主体暂不公开、被动回复窗口/主动消息频控与本网关的异步流程冲突）❌。
> 飞书 Agent/Coze 类云端编排平台不适合本网关：对话编排在云端，而任务状态与 AStudio 通道都在本地。

网关核心不感知渠道。新渠道只需实现一个 adapter，契约与飞书 adapter 相同：

1. **收**：订阅渠道消息，把发送者映射为渠道内稳定唯一 id（`open_id`）。
2. **处理**：调用 `gateway.router.handle_message(open_id, text)`——命令就地返回，对话走投递编排。
3. **回**：把返回文本发回渠道。注意多数渠道有秒级 ack 期限而投递可达数分钟，必须仿照 `gateway/feishu_client.py`：ack 放主线程，`handle_message` 放 worker 线程，回复异步推送。
4. 在 `main.py` 加一个启动分支即可；`registry.json` 按 open_id 隔离，不同渠道天然互不干扰。

| 变量 | 默认 | 说明 |
|---|---|---|
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | - | 飞书自建应用凭证（必填） |

| `ASTUDIO_GUI_ACODE_HOME` | 自动探测 | 对话所在内核 home（overlay） |
| `GATEWAY_DATA_DIR` | `./data` | registry.json 落盘目录 |
| `GATEWAY_EXEC_TIMEOUT` | `600` | 等待模型回复的超时（秒） |

### 模型目录扫描

服务每次启动会连接模型网关 `/v1/models` 重新扫描目录（权威路由来源），甄别哪些自带模型可投递：

- 界面默认路由（astronclaw-auto）不经模型网关，自动排除（投递会 409，实测）
- 其余模型全部实测可用（2026-11-08 逐个切换验证）：spark-x2.6、spark-x2.6-4b、spark-x2.5、xopglm52、xopdeepseekv4pro0813、xopdsv4flash0731in
- 扫描结果缓存于 `data/model_catalog.json`；`/model` 列表以此为准，App 离线时展示缓存

## 投递延迟机制（空闲会话为何约 50 秒）

AStudio 自动化调度器采用**动态睡眠**：每轮执行完毕后睡到最早的到期定义（下限 1 秒、兜底 60 秒）。
网关写入的投递定义若落在调度器已入睡的窗口内，需等本轮睡眠结束（实测约 51 秒，均值约 30 秒，均为官方行为）。

已穷尽评估并**排除**的加速方案（均会深度侵入 AStudio 内部或不可用）：

| 方案 | 排除原因 |
|---|---|
| 直写消息投影表 + 队列提升表伪装 GUI 消息 | 需同时满足事件溯源/指纹/文本分块表一致性，深度侵入核心投影，损坏风险高 |
| 常驻心跳自动化缩短调度相位 | 每次唤醒都是一次模型回合，费用与对话噪音不可接受 |
| MCP 创建自动化（可即时唤醒调度器） | 受会话凭证闸门限制，凭证轮换期恰恰不可用 |
| 内核 `remote-control` 面 | 面向 IDE/CLI 远程控制，模型通道的凭证问题不变 |
| `astron exec` 直连 runtime home | 模型凭证随登录态轮换，外部进程不可复用（实测 401） |

结论：自动化调度是**登录即可用、零凭证、最低侵入**约束下的最快官方路径；执行中的即时通道（`/steer`）不受此限制。

## 长期运行（一次登录，长久远程使用）

目标形态：**本机一次登录 AStudio 并启动网关，之后远程长期使用不掉线**。为此：

- **凭证自愈**：投递/回复/忙碌检测/调度/目录全部本地化（SQLite + 自动化表），AStudio 会话凭证轮换不影响主链路；实时通道（/steer /stop）失效时自动降级，且每次自动化投递会让 App 重新绑定会话、凭证自动回到可用状态
- **进程守护建议**：用「任务计划程序」或 [NSSM](https://nssm.cc/) 把 `python main.py` 注册为开机自启服务，并把 `E:\AStudio Data` 所在盘的 AStudio 设为开机自启并保持登录——两者齐备即"开机即在线"
- **断线自愈**：飞书长连接由官方 SDK 负责心跳与重连（实测断网后自动恢复）；AStudio 重启后网关在下一次调用时重新发现端口与凭证
- **崩溃残留免疫**：超过 15 分钟未结束的历史投递任务视为残留并忽略，不会卡死该对话后续消息；等待超时的投递定义会自动归档，避免恢复后补投过期消息

## 已知边界

- 飞书长连接要求 3 秒内 ack：网关把投递放后台线程，回复异步发出
- 空闲会话的投递延迟见上节（官方调度器相位，最坏约 60 秒）；执行中的会话走 MCP 即时插话
- 凭证轮换不影响主链路：投递/回复/忙碌检测/调度全部本地化；仅 `/steer` `/stop` 的实时形态依赖 MCP，失效时自动降级（排队投递/诚实提示），且自动化运行会重新绑定线程使实时能力自愈
- AStudio 未运行时：`/sessions` 可用（纯 SQLite 只读）；发文字、换模型、`/history` 需 App 在线（返回明确提示）
- 调度新任务 / 换模型会向 App 自动化调度器写入一次性定义并在触发后归档，可在 AStudio 侧自动化列表中看到历史记录
- 自定义绑定模型跨线程切换依赖 `provider_session_runtime` 里存在完整绑定记录；全新机器首次切换 custom 模型前，先在界面里用过该模型一次
- 跨设备共享：把 `data/` 目录放到网盘/服务器即等同实现
